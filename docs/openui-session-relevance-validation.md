# 会话检索中的内容核实与结果展示

Refs #1。处理“搜到旧查询记录，却把它展示为实际项目规划”的问题。关键词搜索负责找候选，Agent 负责结合用户目标判断内容，UI 模型负责展示；不新增关键词黑名单、相关度阈值或第二套规划模型。

## 原因与变更

原搜索按标题优先排序，但标题命中没有正文摘录，Agent 无法直接知道会话是否包含用户需要的内容。采集器又把整批搜索候选交给 UI；即使 Agent 在回答里排除了某条记录，也没有明确发布结果子集的方式。独立 UI 模型不接收历史正文，因此不能靠它重新完成内容核实。

标题命中现在也提供有界、公开的正文摘录；优先给最多两条匹配消息，命中提问时附带下一条公开助手答复（不跨越下一条用户消息，总计最多四条），没有正文匹配时给最近两条消息。匹配消息与相邻答复使用同一个公开消息过滤器，隐藏历史、工具消息和内部运行内容均不会进入摘录。Agent 在摘录不足时使用 read_session 核实上下文；工具说明默认按实际内容核实，只有明确浏览字面匹配或要求选择后读取时保留原始候选，并说明搜索范围有限，不能据此断言历史中绝无相关内容。包含“未找到”字样的真实方案不会被代码过滤。

search_sessions 增加可选 session_keys，用同一关键词缩小到 Agent 根据内容选中的会话，空数组表示没有候选符合目标，省略则保持原关键词浏览。限制仍为最多五个会话，原排序、公开历史权限、当前会话排除和只读语义保留。选定结果仍必须匹配该关键词；未知、已删除、不公开或不匹配的记录不会出现。该字段表达选择范围，不是代码授予的“已核实”标签；语义判断仍依赖 Agent。

原生会话采集收到明确选择时，只替代同一查询的先前候选；不同查询范围保留。选定范围随既有会话查询快照保存，刷新复用该范围，不把此前排除的候选重新加入，不调用模型重新判定；会话更新后若不再匹配或不再公开，则从刷新结果移除。重新搜索更广范围由用户再次提问完成。UI 描述仅增加是否已选择的标志，不向 UI 模型传递历史正文、记录 ID 或单元格。无有效内容时保留结论，实际缺少条件时才提供澄清组件；用户明确浏览原始匹配记录时允许展示这些候选。

扩展的是可选字段，旧快照仍可读取，无数据库迁移。组件说明更新使用现有 library_hash 机制，旧 hash 的历史卡片沿用原文字恢复，不自动重新生成或执行历史动作。

## 验证范围

全部测试、清单生成、静态检查与构建在 GitHub Actions 执行。本地只编辑、审查差异与读取下载的产物。确定性用例验证标题摘录、显式子集与空集、不公开/当前会话排除，以及真实 Gateway 从搜索、读取、选择到快照恢复和刷新不扩大的链路。它们不证明模型语义选择正确。

真实模型验收复用隔离的临时 Gateway 和原生只读工具，增加仅有失败查询、有效方案与失败查询混合、明确浏览全部字面匹配三类问题；混合样本的真实方案故意同时提到此前查询失败，验证不能按否定词粗暴过滤。检查实际选择、页面表格、桌面与手机截图、刷新不重放，并保留调用用量和错误证据。既有搜索选择、读取、空结果、最终相关范围和对比场景继续执行。凭据留在 Codespace 临时文件，生产会话不用于发送验收消息。

有限样本不能保证所有模型和措辞都作出相同判断；读历史仍受原条数和长度限制，未覆盖外部 MCP 或完整历史语义检索。具体提交、运行和部署证据记录于 PR。
