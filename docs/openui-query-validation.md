# 会话表格的受控只读查询

开启自动或始终交互模式，提问“查找之前关于项目规划的会话，显示可筛选的表格”。当 Agent 使用现有 `search_sessions` 工具且实例配置了它的表格适配器时，表格提供“刷新数据”和“查看详情”。刷新重用原搜索条件，详情在表格下显示该记录最近最多八条可见用户/助手消息。需要模型分析时仍使用原有“分析快照”。

刷新和查看详情经当前认证 WebSocket 的 `openui.query` 请求直接调用原生 `SearchSessionsTool` / `ReadSessionTool`，不经过 Agent，不新增用户消息，不调用模型。采用应用所有的显式查询动作，复用官方 Renderer 的 DataTable；模型无需生成 Query/Mutation 语句。Renderer 仍不接收任意工具提供器；外部 MCP 和业务写操作不属于此功能。

## 授权和数据

连接必须通过现有 WebUI 认证、允许列表、会话附着和 OpenUI 订阅校验。请求携带 chat、generation、block、revision、data_ref、operation；详情另带 record_id。客户端不能指定工具名、查询文本、任意会话键或额外参数。只有实际原生搜索工具产生、使用 results/session_key 的配置适配器捕获的表格才带 session_query。服务端核对当前配置、表格来源和列白名单。

刷新仅重放已保存的搜索条件；详情仅允许当前卡片所列出的记录，并由原生会话工具重新检查持久化、公有历史权限和当前会话排除规则。系统、隐藏消息和工具轨迹不进入详情，历史内容按普通文本显示。私有会话、已删除/重建的来源会话、过期 revision、伪造 data_ref/record_id 和额外参数都不能读取数据。WebUI 沿用实例级认证主体，没有新增多用户 RBAC 的承诺。

每实例最多同时执行两个查询，包含排队的截止时间为十秒。前端同步锁拦截重复点击，加载期间禁用读取和分析按钮。读取失败保留原表格并提供显式重试；不会自动重放。断线和宿主/会话切换沿用 epoch 隔离及不重发 OpenUI 请求的规则，迟到详情不能覆盖新的视图。

刷新在独立 UI 数据库内按 revision/sequence 比较并原子保存，保留原始布局、回答、表单草稿和模型用量；新快照更新数据和 sequence，浏览器刷新后恢复最后成功的列表，无自动数据请求。刷新后可以主动再次分析同一条记录，同一 sequence 的重复分析仍受去重保护。详情和本地筛选只存在当前页面，不保存额外历史正文。普通工具表格、缺少只读查询能力的宿主继续保留原有筛选和 Agent 分析操作。组件清单变化沿用现有 library_hash 校验，旧清单卡片安全降级为原始文字，不宣称跨清单恢复已完成。

## 验证

所有测试、静态检查和构建在 GitHub Actions 执行，本地不运行。原生 Gateway 测试覆盖真实会话工具、搜索新增记录、详情白名单、搜索条件不可篡改、转私有后的拒绝、来源会话清理，以及无 Agent/模型请求。前端测试覆盖按点击查询、重复点击、错误重试、纯文本渲染、原位刷新、旧宿主降级和快照顺序。浏览器用例覆盖原生 TCP Gateway、桌面/手机详情、页面刷新不重放查询及继续 Agent 分析。确定性模型夹具验证查询实现，不能作为本轮真实外部模型/MCP 验收。
