# 对话内确认修改会话标题

Refs #1，对应 AT10、AT11、AT18、AT23 的当前会话标题场景。基线为 develop 的 81983a4bfe62aeab2128cf5c1dcbc44e29666d6e；不代表这些验收项针对任意业务写操作都已完成。

## 使用方式

在自动或始终交互模式提问“把这条会话改名为项目开发计划”。模型可生成现有 Form 的单字段变体，新增最后一个可选参数 action:{type:"session.rename",title:"项目开发计划"}，已有位置参数顺序保持不变。用户可以编辑标题，点击预览后查看修改前后的标题，再点击确认。普通问卷仍将答案发送到同一 Agent 会话，不获得写操作权限。无模型的 preview 模式不生成改名表单。

确认通过认证的既有 WebSocket 执行，沿用侧栏 title_overrides 的存储和广播机制，不修改会话正文、不新增用户消息、不调用业务工具或模型。只允许修改当前已附着且已订阅、具有有效完成卡片的持久化 WebUI 会话；客户端不能指定其他目标会话、文件或工具。session_rename 是可选能力，缺失时显示不可用并禁止发送请求；不同组件清单的历史卡片沿用原文降级。

模型生成模式下，原 Agent 接收受支持的标题表单能力说明，避免在确认前宣称成功或自行编辑侧栏文件。后续同会话 Agent 回合按需附带最多六条有界回执与当前侧栏标题，不传内部操作 ID，也不把 prepared/unknown 当成功。回执作为运行时数据传入，不追加伪造的用户/助手历史。

## 状态与恢复

服务端将不可变的准备参数、操作 ID 和结果存入原有 UI sidecar 的 $renames，按 form_id 区分。确认只携带操作 ID，不能临时修改已预览的标题。重复确认返回已保存的结果，不重写侧栏；换参、旧 revision、退役 generation、外来连接均被拒绝。删除会话沿用既有 sidecar 清理。成功结果和准备状态随历史恢复，不会在挂载、刷新或重连时自动执行。

预览保存侧栏文件的内容摘要；确认在现有侧栏写锁内比较摘要并原子写入，保留其他标题、标签和工作台设置。其他页面的侧栏更新会使准备结果冲突，用户需重新预览和确认。这是保守的整个侧栏版本检查，因此无关的侧栏修改也可能要求重新确认；没有新增配置或资源版本表。

准备、执行前的 unknown 栅栏与最终回执分次落盘。普通断线丢失回执后可点击“查询结果”读取已提交状态。若进程恰好在侧栏文件写入与 sidecar 回执提交之间崩溃，则查询返回 unknown，明确要求核对结果，不盲目重放，也不根据标题相同推断成功。此实现不声称跨两个存储的原子提交或任意 MCP exactly-once。确认通过既有 SessionState 所有者与删除/重置串行，校验 generation；沿用实例级认证，未引入多用户 RBAC。

## 验证

测试、类型检查、lint、组件清单生成和构建全部由 GitHub Actions 执行，本地不运行。新增用例覆盖预览不写入、确认落库、双击及重发、结果查询与重启、其他页面修改后的冲突、修订提案后旧 ID 失效、实际写入后丢失回执的 unknown、越权/非法参数/退役会话。浏览器验收复用原生 Gateway、官方 Renderer 和生产侧栏状态 Hook，检查桌面预览、手机结果、真实持久化、刷新不重放及没有额外 Agent 回合。具体执行结果以本 PR 最终提交对应的 Actions 证据为准。

真实模型复验中，改名场景成功，但既有会话读取场景在同一行先给结论再写“Choose one: …”时没有生成选项。原因是自动策略仅识别行首的这类英文指令。沿用现有有界意图规则，将直接选择指令的起点扩展到句子边界，并加入失败原句及普通解释句的回归用例；代码块、引用和纯文本排除行为保持不变。该修复不额外请求分类模型，不按关键词强制生成固定按钮。

代码提交 8b96a461184243cfbe22a4096aafd05695fe21e3 的 [GitHub Actions 确定性验收](https://github.com/yuklcool/nanobot/actions/runs/41184885444) 全部通过：150 个 Python 用例、291 个 Vitest 用例、9 个浏览器用例，以及类型、lint、组件清单、导入边界、独立 wheel 安装 Gateway 和 Docker 启动检查。后续仅补充本说明，功能代码与这次验收一致。

真实模型改名场景在 [首次验收](https://github.com/yuklcool/nanobot/actions/runs/41184168354)、[第二次验收](https://github.com/yuklcool/nanobot/actions/runs/41184564324)、[最终代码复验](https://github.com/yuklcool/nanobot/actions/runs/41184922003) 中均通过，包括编辑、预览、确认、刷新恢复及无额外模型请求。首次整套通过；第二次旧场景暴露上述选择指令漏判，已修复。最终代码复验中改名通过，但旧检索场景仍失败：Agent 将 Meridian 的已确认方案与仅有失败查询的记录一起提交为相关子集，期望一条而实际两条。它是内容相关性筛选问题，当前写操作不依赖该筛选；保留原断言和失败产物，后续单独处理，不能把本次真实模型整套报告为通过，也不据此声称模型语义选择已可靠。

## 宿主接入与关闭方式

宿主必须改动的接入点仅为既有命令路由和侧栏存储：inbound_commands.py 负责认证请求、会话附着校验与保存后的广播，sidebar_state.py 复用同一个写锁和原子保存路径。这两处以及可选 capability 声明是后续跟随上游时需关注的合并点；执行与回执集中在独立的 openui_rename.py。没有更改会话正文或现有侧栏 API 的存储语义。需要关闭实验功能时，将现有 channels.websocket.openuiEnabled 设为 false 并按原部署方式重启，恢复原生文字会话；标题和会话数据保留，不新增回滚配置或数据库迁移。

本批仅登记当前会话标题操作。外部 MCP、其他资源写入、跨进程侧栏并发以及全部 P0/P1/P2 验收不在本批完成范围内，Issue #1 保持开启。
