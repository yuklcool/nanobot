## 现场验收

真实请求使用已配置的 Provider 和现有 SQL 只读 MCP，在浏览器新建普通会话并继承自动模式。原生回答直接生成对话内表格和条形图，没有为展示创建 Excel 或安装绘图包。

| 场景 | 浏览器及真实后端结果 |
| --- | --- |
| RTU 汇总 | 9 行汇总表及条形图可见，捕获值逐单元匹配真实 SQL 回执，无源截断。 |
| RTU 筛选与排序 | 筛选为一行；表头升序的实际数值顺序已核对。操作前后原生用户/工具/SQL 计数不增加。 |
| RTU 点击记录 | 同一 Session 的用户消息从 1 到 2，工具从 4 到 5，真实 SQL 从 1 到 2；新结果为一行明细表，值与第二次查询回执一致，两个视图均 complete。 |
| RTU 刷新恢复 | 两轮表格与图表恢复，用户/工具/SQL 计数不变，未重放查询。 |
| 单灯汇总与筛选 | 2 行真实汇总表及条形图可见，筛选为一行；前后用户/工具/SQL 计数均为 1/4/1，数据逐单元匹配回执。 |

RTU 本地操作前后的全实例模型物理请求总数均为 448；第二轮后的排序及刷新窗口均为 451；单灯本地筛选窗口均为 457。该数据库没有会话维度，以上仅作为安静窗口的全实例前后对照，不能冒称逐会话 Provider 计数。原生消息、工具和 SQL 计数按各自 Session 核对。数据库检查只读，不触发工具或模型。

单灯点击记录后，同一 Session 的用户消息从 1 到 2、工具从 4 到 5、真实 SQL 从 1 到 2；第二轮显示全部 35 行明细，逐项匹配真实回执，无源截断。刷新后两张表格及图表仍在，用户/工具/SQL 仍为 2/5/2，全实例模型计数仍为 460。两场景均无 SQL 错误，最终浏览器 error/warn 日志为空，未出现 Zod 错误或裸 Lang。重部署后原问卷仍保留五个 complete 视图及两个独立 submitted 表单。

原始截图、DOM、真实回执逐项核对及计数记录保留在本地 `tmp/issue1-acceptance-2026-11-12` 和授权部署主机，未上传到公共仓库。公开报告只保留验收元数据，不包含凭据、连接配置或业务明细。

## 维护与交付边界

main/stable 均启用保护，定制代码没有写入这两条分支；定制功能通过 develop 功能分支和 PR 交付。上游检查已有官方标签核对、独立试合并、冲突报告和不可变候选传递；v0.4.1 已知冲突仍在 #29 跟进。

主体实现位于 nanobot/openui、独立 WebUI openui_* 模块、webui/src/openui 和共享动作类型中。需与上游一起维护的接入点包括 WebSocket 能力/路由、inbound_commands、Gateway 服务组装、会话生命周期/只读历史锚点、原生侧栏，以及消息容器、客户端和新建会话模式入口；不声称未来升级无冲突。本批仅补齐原生能力说明和可见回答锚点，没有改写 Agent Loop、Provider、MCP 或 SQL 执行器。

按用户要求直接替换旧交互容器，不创建备份；持久配置、会话和 sidecar 保留，原有独立服务保持运行。回滚时先关闭 channels.websocket.openuiEnabled，再使用固定且兼容数据格式的已验证产物按原方式替换容器；保留原生会话和 UI 数据，不让旧代码写入未知 schema。前后端清单须一起部署，详见 [维护入口](openui-integration.md)。

本次交付固定 v0.4.0 候选及其安装产物，没有发布 tag、GitHub Release、PyPI 或公开镜像。直接数据读取限已有受控会话工具，Mutation 限当前会话标题；没有实现任意业务写操作、照明控制或业务权限平台。真实验收是当前配置模型与选定只读样本的结果，不代表所有模型和措辞的普遍成功率。
