# 基于对话上下文选择交互展示

Refs #1。修复“最终回答说没有结果，却追加多套空表”的展示链路。此次评估覆盖重复查询、空数据、有效数据、需要澄清的条件、对比多个数据集，以及筛选和刷新后的状态变化。搜索是否命中由原有搜索工具负责，此次不改变检索语义。

## 根因与处理边界

采集层保存的是一轮工作中的授权快照，不是最终展示计划。原先生成层一旦收到任何数据集，就用固定英文指令替换最终回答；模型只看到表格标题、列和行数，无法结合回答判断这些数据是否仍相关，也缺少来源、搜索范围和时间信息。前端又对原始空数据和本地筛选无匹配使用同一种完整表格结构，使内部的多次尝试变成多套重复面板。

展示选择继续由现有独立 UI 模型完成。它同时接收原问题、最终公开回答和候选数据概况，选择最少且有用的交互；同一任务中的中间尝试无需逐一展示，明确要求的不同数据范围或对比应保留。没有额外价值时输出空 Panel；真正需要用户补充条件时，使用现有 Choices/Form。空数据仍可用于用户明确需要反复查看的列表，不按“没有找到”等文本关键词强行隐藏，也不在采集时删除空快照或按工具名合并所有结果。

概况增加来源工具、采集时间及原生会话搜索的原搜索词，继续排除原始工具输出、记录 ID、单元格值和内部当前会话键。原问题作为有界、不可变的 question 字段随 UI 快照保存，重试复用相同上下文，不重跑业务工具。旧快照缺少此字段时按空字符串读取；不迁移数据库，不改变协议版本。新字段是可选的；旧客户端仍遵循组件清单 hash 协商。组件源文件变化会更新清单，既有不同 hash 的历史卡片沿用现有文字展示规则，不自动重新生成或执行历史动作。

代码负责可信数据引用、现有权限与状态，不实现一套业务意图规则或新增规划模型。自动模式仍是原有有界触发策略，允许把空查询交给 UI 模型判断是否值得澄清；不额外增加分类请求。无模型的 preview 只预览实际数据行，首次查询为空时保留原生回答，不创建空卡片。

## 组件状态

| 场景 | 预期表现 |
| --- | --- |
| 多次搜索均无结果，最终回答已足够 | 保留原生回答，模型可输出空 Panel；不强制生成表格或通用建议 |
| 空结果后确实需要补充条件 | 根据回答中的实际问题生成短表单或选项 |
| 空尝试后得到有效结果 | 展示相关的最终结果，不把中间空尝试一起铺开 |
| 用户要求比较不同查询范围 | 可分别展示多个相关数据集，不按来源工具粗暴去重 |
| 模型选择了空数据，或原表刷新后为空 | 紧凑标题、时间和空状态；有只读能力时保留刷新，不显示空表头、筛选和 0/0 |
| 已有数据被本地筛选至零行 | 保留筛选输入，显示无匹配状态及清除筛选；操作不发送消息、工具或模型请求 |
| 加载或查询失败 | 保留已有数据；显示加载或明确错误/重试，不同时显示“没有结果”造成误解 |

新增“暂无记录”和“清除筛选”同步十种语言。组件控件继续使用应用语言设置，模型生成的标题、选项和表单匹配公开回答语言；不因某条消息更换应用全局语言。

## 验证与限制

测试、静态检查、清单生成及构建均在 GitHub Actions 执行。本地只修改源码、审查差异和下载产物。确定性回归验证上下文传递与隐私边界、重试复用问题、原生双次空搜索、空 Panel 的恢复、空结果后的澄清表单、空数据组件、清除筛选，以及刷新至空后保留刷新能力。

可选真实模型浏览器验收复用已有隔离 Codespace runner、临时人工会话及只读 search_sessions/read_session，新增双空查询、空尝试后有效结果、两个明确对比范围三组场景。每组核对实际捕获的数据行数、渲染表格数量、桌面/手机截图和页面刷新不重放；它验证真实模型的选择，确定性夹具不代替这部分证据。

模型展示选择仍有概率性，单个模型、有限样本不能证明任意业务工具和语言都始终选择正确。保留完整候选快照和原生回答，以便继续审查；不引入静默修写模型布局、额外自动重试或外部 MCP。实际执行结果与提交身份在 PR 中记录。
