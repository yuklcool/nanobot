# 现有 SQL MCP 结果展示

Refs #1，开发基线为 develop `14782dd60a69ec2d1659cc7e0f2b326def02d01d`，对应 AT04、AT08、AT13、AT17。复用现有 Collector、DisplayTable、DataTable、DataChart 和记录分析动作，解决现有 SQL 回执没有独立行 ID、汇总与明细列不同的问题，不引入业务组件、SQL 执行器或额外依赖。

## 配置与边界

`channels.websocket.openui.tables` 只登记当前实例已有并获准展示的工具。照明实例已观察到工具名 `mcp_mcp-sql-http_sql_query_readonly`，回执为 `ok:true`、`rows` 数组和布尔型 `meta.truncated`。示例白名单来自此前 RTU/单灯报警查询实际返回的列；管理员应按本实例允许展示的字段配置，不自动公开其他字段：

```json
{
  "mcp_mcp-sql-http_sql_query_readonly": {
    "title": "报警查询结果",
    "resultFormat": "sql_readonly",
    "idField": null,
    "columns": {
      "报警类型": "报警类型",
      "报警条数": "报警条数",
      "RTU编号": "RTU编号",
      "灯杆编号": "灯杆编号",
      "道路": "道路",
      "报警时间": "报警时间",
      "末次发生时间": "末次发生时间",
      "报警信息": "报警信息"
    }
  }
}
```

SQL 格式显式读取 `rows`，无需修改默认 `recordsKey`。白名单按本批首行实际字段投影，后续捕获行必须包含这些列；未登记字段和连接、请求、计时等元数据不进入展示快照。源查询失败、缺少可靠截断标记、没有获准列或字段类型非法时拒绝适配，保留原生回答。单次输入 256 KiB、单表 50 行/8 列、单轮 4 表/64 KiB 的原有限制继续生效。模型生成的其他列别名未获登记时不会自行公开，应由管理员依据实际业务合同调整白名单。

协商成功且使用模型交互模式时，原生 Agent 的既有能力说明同时描述对话内表格、排序/筛选、图表和指标：通过已授权工具取得数据并给出可读回答，交互视图由已有 UI 阶段生成，不为这些视图创建 Excel、图表图片、HTML 或安装绘图依赖。用户明确要求下载或导出文件时仍走原文件流程。该说明不注入关闭、旧客户端或 preview 回合，不改变工具权限和文件技能本身。

附件消息后的重复流式确认由原生客户端隐藏；UI 阶段同样跳过这些隐藏片段，将视图挂到实际可见的回答上。附件仍由原流程展示和下载，不修改原生消息投影或重放业务工具。

显式 `idField:null` 生成的 `row_1` 等只在 data_ref、block、revision 和 Session generation 内定位已捕获行，重复业务值仍是不同快照行。分析动作由服务器从快照取回授权值，在原 Session 发起 Agent 回合；浏览器不能改写这些值、选择工具或直接执行 SQL。带实时读取按钮的 Query 仍仅限已登记的原生会话搜索，不为 SQL 表格开放任意查询重放。

`total_rows` 表示源工具本次实际返回的行数；本地捕获更少时显示捕获数/返回数。`source_truncated:true` 表示源服务也截断，显示返回行数后缀 `+`，不声称完整数据库总量；单值指标拒绝这种快照。这个可选字段随组件清单一起部署，旧清单仍保留原文降级，历史读取不重跑 SQL。回滚到不认识新字段的安装前应关闭 OpenUI，并保留 sidecar 数据。

## 验证

Python 测试覆盖白名单投影、不同结果列、重复值的独立快照 ID、上下游截断、失败回执拒绝，以及原生 Gateway 中选择快照行后同 Session 再次执行只读工具。前端回归覆盖旧格式兼容、排序/筛选不产生请求和源截断时禁止单值总计。代码检查、清单生成、构建和自动化测试仅在 GitHub Actions 执行。

真实照明验收使用已部署产物，核对 RTU/单灯查询回执与表格一致，本地筛选/排序不增加 Agent/Provider/SQL 调用，记录分析在同 Session 再次执行实际 SQL MCP 并生成新视图，刷新后保持快照且不重放查询。固定提交、产物、现场记录和 AT01–AT24 总表在整体验收报告中收口；本段定义操作和边界，不代表尚未执行的现场检查已经通过。
