# 交互组件的持久化会话校验

Refs #1。在照明业务实例的并行部署验收中发现，普通回答完成后，交互组件可能生成失败，刷新后也无法恢复或提交，返回 `STALE_GENERATION`。该问题与表单内容无关：原生展示历史追加会推进存储版本，随后标题等元数据更新会使完整历史缓存失效，而 OpenUI 原先依赖该缓存中的身份判断会话是否存在。

OpenUI 现在通过会话状态所有者读取已提交的轻量会话头，同时核对 generation、持久化策略和 WebUI 元数据，不再把缓存缺失当作会话失效。读取不会创建不存在的会话，不加载聊天历史或 Provider checkpoint，也不会放宽临时会话和已重置会话的边界。会话退休清理复用同一路径。

回归覆盖原生历史追加、标题更新之后的组件恢复和草稿保存，以及重新创建状态所有者后的轻量读取、缺失会话不创建和临时会话策略。测试、检查及安装包构建仅在 GitHub Actions 运行；真实部署验收单独记录，不将模型限流或静态页面可访问视为交互通过。
