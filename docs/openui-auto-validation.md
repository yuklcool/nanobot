Refs #1。开发基线为 `develop` 的 `ff5f15054db1e35de25289e805854d5287920005`。本批范围是按需生成组件，以及使用现有 `search_sessions` / `read_session` 工具验证同会话只读交互；不新增业务工具、直接 Mutation 或外部 MCP 服务。自动化验证只在 GitHub Actions 运行，本文中的命令不代表已执行结果，实际证据以本 PR 的确切提交和 CI 为准。P0/P1 整体验收与真实外部模型/MCP 验收继续保持未完成。

## 输出模式

聊天中的“交互组件”提供三个选项，初始为关闭；切换会话或刷新后恢复关闭，历史组件仍可查看并显式点击。

新建普通会话页也可在发送第一条消息前，从页头操作区选择模式；仅选择模式不会创建会话或发送消息。创建会话后，客户端先完成 OpenUI 订阅，再将该次选择交给新会话，首条消息即使用所选模式。订阅失败会明确拒绝创建流程的完成，不发送首条消息，保留草稿选择以便重试。临时会话继续隐藏该入口，不创建持久化 UI 数据；不支持 OpenUI 的宿主也不显示入口。

| 界面 | 协议 | 行为 |
| --- | --- | --- |
| 关闭 | `markdown`，客户端省略 `ui_mode` | 沿用普通回答，不捕获 UI 数据，不发起 UI 模型请求 |
| 自动 | `auto` | 服务端结合当前公开问题、最终回答和显式授权的数据表判断是否生成；不增加意图分类模型请求 |
| 始终 | `openui` | 保持原来的显式启用行为，每个符合条件的持久化 WebUI 回合尝试生成组件；无有用交互时仍可返回空面板 |

自动模式第一版使用有界的中英文规则：存在已捕获的数据表、明确要求按钮/表单/交互，或回答明确向用户询问选项、确认或缺失信息时进入生成；没有这些信号的普通解释保留文字。用户明确要求纯文字时跳过，即使有数据表也不发起 UI 请求。回答中的代码块和引用行不用于识别追问。规则可能漏判其它语言或隐含意图，此时可选择“始终”；不宣称模型级的通用语义识别。

`channels.websocket.openui.generation` 继续独立控制生成方式：`preview` 只显示已捕获表格且不调用 UI 模型；`model` 使用冻结的回合 Provider 生成组件。自动模式不会修改该配置，也不会增加 API Key 或隐藏的分类请求。现有超时、并发、输出 token 和重试上限保持生效。

服务端在现有 OpenUI protocol 1 capability 增加可选 `modes` 字段，值为 `["markdown", "openui", "auto"]`。旧客户端仍可发送 `openui`；新客户端连接未声明自动模式的旧宿主时只提供关闭/始终。重连到不支持自动模式的宿主会清除自动选择，不自动改成额外模型请求更多的始终模式。未通过原 WebUI 身份验证和能力订阅的请求不会启用 UI；非法模式返回 `invalid_ui_mode`，不进入 Agent 队列。

## 现有只读工具示例

无需外部 MCP 即可使用项目已有的持久化会话搜索和读取工具。把以下数据适配配置合入现有 `channels.websocket.openui.tables`；这是显式选择展示字段，不会默认开启跨会话内容展示或更改原工具访问权限。

```json
{
  "search_sessions": {
    "title": "相关会话",
    "recordsKey": "results",
    "idField": "session_key",
    "columns": {"title": "标题", "updated_at": "更新时间"}
  }
}
```

在已有至少一个可搜索的持久化会话时，选择自动模式并提问：“搜索与旅行计划相关的历史会话，列出结果，让我选择一条后再读取原文。”`search_sessions` 返回的会话标识用于记录身份，表格只显示白名单中的标题和更新时间，不复制搜索结果中的历史正文或 excerpts。标题、标识等仍受现有字段长度上限约束，超限适配会拒绝展示并保留普通回答。

筛选表格只改变浏览器本地状态。点击“分析快照”时，服务端从已保存的数据构造可信记录消息，在原 Session 发起新回合；Agent 根据用户意图选择 `read_session` 查询详情。它沿用原工具权限和 Agent 决策，不保证每个真实模型都必然选择同一个工具。不会让浏览器指定任意工具、伪造记录数据或直接执行写操作；刷新历史不重放查询或动作。

记录动作在对话中只显示简短的表格和记录摘要；可信记录标识及字段数据复用原生 RuntimeContextBlock 传入 Agent，并由既有元数据在历史展示时移除，不把内部 JSON 堆进消息气泡。摘要仍由服务端校验；不同记录即使摘要相同也使用独立动作身份，相同动作的重复点击不再次发送。

## 表单草稿与提交恢复

本批基于 `develop` 的 `52275e1009b7e480eb3ca8c68d1e19a6ae7d54be`，补齐 AT13 的表单相关路径。新增可选 capability `form_recovery: true`，只有宿主明确声明支持时客户端才请求 `openui.form`。未声明能力的宿主继续沿用现有表单发送路径；原 WebUI/OpenUI 协议号不变。

`Form` 字段可声明 `persist: true`，仅用于项目名、优先级等非敏感信息，界面会在对应字段下提示自动保存。未声明的字段只留在组件内存中，草稿保存请求不包含其填写值。组件目录明确禁止索取密码、token、凭据等秘密；这不是对任意用户输入的敏感信息检测器。提交是用户显式发送普通会话消息，消息正文仍按原会话策略保存，不把“不保存草稿”误解为“不保存已发送消息”。

草稿编辑停止约 500ms 后写入现有 generation-scoped SQLite snapshot 的 `$forms`。使用不可变 revision 下 Panel 子组件的位置区分表单，不依赖 DOM ID，也不增加 Lang 解析器。每次保存使用现有 state_version CAS，保留 `$question` 和其它表单状态；同一客户端串行保存，跨客户端冲突明确报错，不覆盖较新草稿。刷新、重新连接或切换回该会话，从服务端已确认保存的草稿恢复；离开页面前尚未获得保存确认的输入不保证恢复。

`openui.form` 接收有界的展示 schema 和字段值，服务端验证必填、枚举、字段数量与长度，仅保存显式允许的字段。展示 schema 是经过认证的客户端输入，服务器不宣称它与模型 Lang 的业务语义一致；该接口不授予工具权限，不支持业务 Mutation。首次保存后 schema 指纹固定，改参拒绝。提交用当前完整值进行验证和准备，不依赖尚未完成的防抖保存。

提交准备在同一快照中保存服务端请求 ID、内容摘要和允许保存的字段；不在准备阶段保存完整消息或未允许的值。刷新不会自动发送准备好的动作。显式再次发送复用该 ID；只有消息已入队并写入现有动作账本 accepted 收据后，服务端才把表单标为 submitted。重复点击、重复请求和重启后的重放不再次入队。“已提交”仅代表消息获准进入会话，不表示 Agent 或业务工具执行成功。

保存失败保留页面内容，显示错误和“保存草稿”重试入口。发送未确认时也保留输入，显式重试复用原请求 ID。已经建立入队围栏却没有 accepted 收据的动作显示“提交状态未知”，禁止从该表单再次发送，要求先查看会话；进程可能已入队，不能通过换新 ID 自动重发。该批不补充任意业务工具的 exactly-once 执行或崩溃对账。

GitHub 验收增加：服务重启后恢复允许字段和提交收据、未允许字段不进入草稿、非法枚举和缺失字段拒绝、跨 generation/会话隔离、状态版本冲突、相同请求最多一次入队、未知结果不重放、保存/发送失败保留填写内容，以及浏览器填写→保存→刷新恢复→原 Session 提交→刷新锁定的完整路径。组件 manifest 通过 GitHub 的 workflow_dispatch `refresh_manifest` 生成并下载提交，本地不执行测试、类型检查或构建。实际结果仍以当前提交的 GitHub CI 为准。

## 完整问卷

本批基于 `develop` 的 `8c1bba3d5e956bab4ee6ed34b9f34b6cce44279f` 扩展现有 `Form`，支持 1–12 个字段、单选、多选、下拉、文本及选填题。默认仍必填；旧的文本和下拉调用保持原行为。不新增问卷服务、存储表或业务执行入口。

```text
root = Panel([survey])
survey = Form("就业情况调查表", [{label: "是否考虑离职？", type: "radio", options: ["是", "否"]}, {label: "主要原因", type: "checkbox", options: ["薪酬", "压力", "其他"], when: {field: 0, value: "是"}}, {label: "其他原因", when: {field: 1, value: "其他"}}], "填写后将答案发送到当前会话。", "questionnaire")
```

`when` 仅能引用前面的选项题，编号从 0 开始；单选按相等、多选按包含判断。父问题隐藏时子问题也隐藏，客户端清空隐藏答案，服务端再次清除隐藏值。多选提交按选项定义顺序规范化，服务端拒绝非法枚举、重复值、缺失必填或错误类型。整表提交继续复用同会话消息、现有动作账本和提交恢复，消息总长最多 4000 字符；普通后续问题仍为 2000 字符。

自动模式识别公开回答中的中英文问卷标题与编号问题或复选项；普通解释、代码/引用示例和明确纯文字请求不因此触发。模型生成提示要求把实际题目与选项转换成一份问卷，不以“优化问卷”等后续按钮代替题目。完整、合法且独占 Panel 的 `presentation:"questionnaire"` 表单可替代主消息中的静态问卷，原文可展开查看；使用官方 SDK parser 判断完整性，解析失败、生成中或能力不匹配时保留原文。

员工状态、收入等个人问卷答案默认仅留在当前组件内存，不自动保存草稿；刷新会清空尚未提交的个人答案。显式提交仍会作为普通会话消息保存，不表示匿名或面向外部的数据收集。提交收据恢复后锁定表单，刷新不重发。旧 library_hash 的历史组件继续按现有规则不渲染，其原始回答保留；需要重新生成才能使用新增题型。

GitHub 验收覆盖多选和条件校验、个人答案草稿隔离、允许字段恢复、完整问卷替换原文、条件切换清空、整表发送与恢复锁定；浏览器通过真实 SDK 和原生 Gateway 填写六题员工调查表，并产出桌面、手机和暗色截图。Provider 为确定性夹具，此证据不代表真实外部模型生成质量已验收。公开问卷发布、多人员回收及统计后台不在本批范围内。
