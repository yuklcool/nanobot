# 表单草稿的多页面同步与冲突处理

Refs #1，限定处理 AT13、AT14 中现有 Form 的草稿同步，基线为 develop 的 8b61b8ac0658a493a38a2d759b3b038535934e50。不新增组件类型、照明业务、工具、配置、协议字段或数据库结构；组件清单不变。

原表单仅在首次挂载时载入服务端草稿。其他页面保存后，本页输入仍保留旧值，自动保存可能把它当作新编辑回写。现在将已确认草稿与本页未保存输入分开处理：已保存字段未修改时载入最新草稿；本页存在不同的未保存编辑时暂停自动保存与提交，保留输入并提供“载入最新”或“保存本页”的明确选择。仅保存在内存的字段不加入草稿请求，载入最新草稿时仍按既有条件题规则保留或清空。

草稿沿用现有客户端串行队列和后端 state_version 比较。排队开始时核对同一表单的草稿是否已变化；迟到的保存回执不能盖过客户端已接收的新草稿，也不能解除尚未解决的冲突。其他表单或无关状态更新不会因为整个块的版本变化就被认定为该表单冲突。保存与冲突处理不新增 Agent 回合，不自动发送问卷答案。

测试、类型检查、lint 与构建仅在 GitHub Actions 执行。本批用例覆盖未编辑页面的同步、内存字段保留、未保存编辑冲突、两种显式解决方式及迟到保存回执；原生 Gateway 浏览器用例在两个实际页面中验证广播、手机宽度冲突提示、真实持久化与刷新不重发。测试使用原有确定性 Provider，不扩展真实模型、历史内容相关性或照明业务的验收结论，具体运行结果以 PR 对应提交为准。
