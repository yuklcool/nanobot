# 会话重置与删除后的交互清理

Refs #1，基线为 develop 的 17ca7ca5441b1a37915ff004cc03cbf0f53550da。本批补齐 `/new`、SDK clear/delete 和既有 WebUI 删除路径的 OpenUI 清理，不增加组件、业务工具、配置或数据库结构。当前没有原地删除部分展示历史的独立入口；上下文预算裁剪、压缩和会话分叉保留原历史，因此保留原会话的卡片与草稿，不新增历史截断接口。

会话状态所有者在持久会话重置或删除提交后，通知订阅者确切的旧 generation。OpenUI 仅清理该身份下的卡片、表单草稿、标题操作回执和动作记录，持久化失效标记，取消旧 UI 任务并释放旧模型引用。并发创建的新 generation 及其他会话不参与清理；临时会话不产生持久化清理通知或失效标记。核心会话层提供无 WebUI 依赖的异步订阅入口和可选的重置身份校验，旧文件状态删除观察器保持原职责。通知在存储操作之外执行，避免取消 UI 任务时等待会话读取造成死锁；已接受的清理在调用方取消后仍完成，异常明确返回。

统一会话模式的执行键与页面展示键不同，且入站消息可携带执行键覆盖。`/new` 在清空原执行会话后，使用现有 channel/chat 键映射重置当前持久 WebUI 的展示历史，并校验入站时已确认的展示 generation；不会清空其他页面会话或创建临时聊天的持久历史。SessionState、命令路由及 `/new` 处理器是本批需要关注的上游接入点，Agent Loop/Runner 不改动。

WebUI 沿用现有 `session_updated` 的 `thread` 通知刷新历史与 OpenUI 快照，不增加协议或客户端能力。旧页面的保存、重试和表单动作仍需核对当前 generation；动作账本另外在事务内检查持久化失效标记，防止先通过身份检查、后在清理完成时迟到的动作重新插入旧记录。刷新与进程重新打开附属库均不能恢复已清理的数据，不自动重跑工具或提交问卷。

回归覆盖 SDK 清空/删除和原生命令、旧草稿及动作记录清理、旧请求拒绝、其他会话保留、新会话继续生成、流式 UI 取消，以及清理期间取消调用方并重新创建会话。浏览器使用实际认证 WebSocket、生产客户端和 Renderer，在两个页面中验证 SDK 清空后表单移除、刷新不恢复、后续问卷为空且无额外恢复请求。SDK 调用控制仅存在于隔离浏览器夹具，不加入产品 HTTP 接口。`/new` 测试替换无关的后台归档任务，不将其作为归档能力验收。

测试、lint、类型检查和构建仅在 GitHub Actions 执行，结果以 PR 的确切提交与运行证据为准。本地不执行。进程在原生会话提交与附属清理之间崩溃后的自动对账、历史版本遗留数据回收和跨版本迁移不在本批范围内；当前 generation 校验仍阻止旧卡片操作，不据此宣称跨两个数据库的原子提交，也不关闭 Issue #1。
